# 商城订单详情物流查询设计

## 背景

当前商城订单详情页只展示订单里的物流公司与物流单号，没有站内物流轨迹。商家侧已经可以录入和更新物流信息，但用户侧仍需要复制单号去外部站点查询。

这次只处理小程序商城订单详情页的物流展示，不改订单列表、不改后台发货工作台、不做物流通知、不做退货逆向物流。

## 目标

在订单详情页为已录入物流的订单提供站内物流能力：

- 展示物流公司、物流单号、发货时间、最近状态
- 支持展开物流时间线
- 支持复制物流单号
- 当第三方轨迹结果不可靠时自动降级，只展示基础物流信息和提示，不展示可疑时间线

## 非目标

- 不新增订单列表物流入口
- 不新增物流订阅、物流提醒
- 不新增退货物流查询
- 不做物流商维护后台
- 不把第三方原始响应直接暴露给前端

## 方案选择

采用“站内可用版”：

1. 后端新增商城订单物流查询接口，由服务端统一代理第三方物流查询。
2. 先使用订单已有的物流公司和物流单号。
3. 当订单未保存物流公司时，调用公开可访问的隐藏识别接口自动识别承运商。
4. 明细轨迹只在结果满足最小可信条件时返回。
5. 不满足可信条件时返回降级态，前端不展示轨迹时间线。

## 第三方依赖策略

### 自动识别

优先使用：

- `http://www.kuaidi.com/index-ajaxselectinfo-<trackingNo>.html`

该接口当前可直接访问，并且对测试单号可稳定返回识别结果。

备用识别：

- `https://trace.fkdex.com/auto.php?mailNo=<trackingNo>&callback=callback`

### 轨迹明细

优先尝试：

- `http://www.kuaidi.com/index-ajaxselectcourierinfo-<trackingNo>-<companyCode>.html`

但该接口对部分单号存在历史脏数据或结果冲突，因此不能直接视为真实轨迹。

本期不做多家第三方聚合，只做单源查询 + 可信性判定 + 降级。

## 后端设计

### 新增接口

- `GET /api/mall/orders/logistics?orderId=<orderId>`

鉴权方式沿用商城订单详情接口：必须带当前登录用户 `sessionToken`，并且订单必须属于当前用户。

### 返回结构

返回统一结构：

- `queryMode`
  - `timeline_available`
  - `fallback_only`
- `company`
- `companyCode`
- `trackingNo`
- `shippedAt`
- `latestStatus`
- `latestTime`
- `timeline`
- `fallbackReason`
- `officialQueryHint`

其中：

- `timeline_available` 时返回轨迹时间线
- `fallback_only` 时 `timeline` 为空数组，前端只显示基础物流信息和提示

### 可信性判定

后端明细结果仅在以下条件满足时认定为可展示：

1. 订单存在物流单号
2. 已知或识别出的物流公司编码非空
3. 第三方明细接口返回成功
4. 轨迹数组非空
5. 轨迹文案中不包含明显无效信号，例如：
   - `查无结果`
   - 空时间
   - 空文案

本期不做复杂的跨源比对与物流文本语义校验，避免过度设计。只要出现明显异常，就降级，不展示时间线。

### 内部模块拆分

新增一个聚焦物流查询的服务文件，负责：

- 公司名到公司编码的归一化
- 第三方自动识别
- 第三方轨迹查询
- 第三方数据清洗
- 轨迹可展示性判定

`mallService.js` 只负责：

- 校验用户是否有权限查看该订单
- 读取订单物流字段
- 调用物流查询服务
- 拼装 API 返回值

## 前端设计

### 订单详情页展示

在现有“物流信息”位置升级为独立物流卡片，包含：

- 物流公司
- 物流单号
- 发货时间
- 最近状态
- 复制单号按钮
- 展开/收起轨迹按钮

### 展示规则

- 没有物流单号时：沿用当前页面提示，不渲染物流卡片
- `timeline_available`：显示最近状态和时间线
- `fallback_only`：显示基础信息和“暂时无法拉取轨迹，请复制单号到官网查询”的提示，不显示时间线

### 交互

- 进入订单详情页后，若订单有物流单号，则并行请求物流查询接口
- 点击“复制单号”调用小程序复制 API
- 点击“查看物流轨迹”只控制本地折叠状态，不重复发请求

## 错误处理

- 第三方请求失败：接口仍返回 `ok: true`，但 `queryMode = fallback_only`
- 当前用户无权限查看订单：返回鉴权或无权限错误
- 订单不存在或无物流单号：返回空物流结果，不抛出第三方异常

## 测试策略

本仓库没有现成后端单测框架，本次补一个最小 `node:test` 测试文件，先覆盖：

- 公司名归一化
- 第三方识别结果清洗
- 轨迹结果是否应降级的判定

实现完成后至少执行：

- 新增 `node:test` 文件
- `npm run check:miniprogram`
- 对修改过的后端文件执行 `node --check`

## 风险与约束

- 公开隐藏接口属于非正式依赖，未来可能变化
- 因此必须始终保留降级路径，不能让页面依赖轨迹时间线才能工作
- 本期只追求“多数正常单号可在站内展示物流”，不承诺所有物流源都可稳定返回完整轨迹
