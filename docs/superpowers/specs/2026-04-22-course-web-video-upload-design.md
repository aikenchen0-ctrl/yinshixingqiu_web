# 课程后台视频课节纯上传设计

## 背景

当前课程后台的课节管理页里，视频课节通过手工填写视频地址来录入视频资源。后端已经提供视频上传接口，前端也已有通用视频上传方法，但课程后台没有把这条上传链路接到课节编辑页。

这次只处理 Web 端课程后台的视频课节上传体验，不改小程序课程播放页、不改后端上传协议、不改课程或课节的数据结构。

## 目标

把课程后台视频课节的录入方式改成纯文件上传：

- 运营在 Web 端点击上传按钮选择视频文件
- 前端调用现有视频上传接口完成上传
- 上传成功后自动把返回的资源地址写入 `lessonForm.videoUrl`
- 页面只读展示当前已上传的视频结果
- 保存课节时仍沿用现有 `videoUrl` 字段提交

## 非目标

- 不保留手工粘贴视频地址入口
- 不新增上传进度条
- 不新增拖拽上传
- 不新增批量上传
- 不新增视频删除接口
- 不修改课程课节保存接口的字段定义
- 不修改后端 `/api/uploads/video` 行为

## 方案选择

采用“纯上传 + 只读展示”方案：

1. 视频课节表单移除可编辑的视频地址输入框。
2. 新增一个上传视频按钮和隐藏文件选择控件。
3. 选中文件后直接调用现有 `uploadPlanetVideo(file)`。
4. 上传成功后把返回 URL 回填到当前课节表单。
5. 若课节原本已有视频地址，则作为当前视频只读展示，用户只能通过重新上传替换。

这样可以把运营录入路径统一收束到上传动作，避免继续依赖手工填写外部地址。

## 前端设计

### 页面范围

仅修改课程后台课节管理页：

- `admin-web/src/pages/admin/CourseManagementPage.tsx`

### 交互设计

当课节类型为 `VIDEO` 时：

- 显示“上传视频”按钮
- 显示当前视频状态区域
- 不再显示可编辑的视频地址输入框

当前视频状态区域的展示规则：

- `lessonForm.videoUrl` 为空时：提示“暂未上传视频”
- `lessonForm.videoUrl` 非空时：显示“已上传视频”及只读地址文本
- 若是编辑已有课节，历史 `videoUrl` 进入表单后按同样规则展示

上传按钮行为：

- 点击按钮后触发隐藏的 `input[type=file]`
- 仅接受视频类型文件
- 上传过程中按钮禁用，文案切换为“上传中...”
- 上传成功后更新 `lessonForm.videoUrl`，并给出页面级成功提示
- 上传失败后保留原表单值，并给出页面级错误提示

替换上传行为：

- 如果当前已有视频，按钮文案改为“重新上传视频”
- 新上传成功后直接覆盖当前 `lessonForm.videoUrl`

### 表单提交规则

- 课节保存时继续通过现有 `saveAdminCourseLesson` 提交 `videoUrl`
- 上传未完成时，禁止点击“创建课节/更新课节”
- 若视频课节未上传视频就保存，沿用当前后端/业务规则，不额外引入本期外的新校验

## 复用能力

直接复用现有前端上传方法：

- `admin-web/src/services/planetWebService.ts`
- `uploadPlanetVideo(file)`

直接复用现有后端接口：

- `POST /api/uploads/video`

当前后端约束保持不变：

- 支持 `MP4`、`MOV`、`M4V`、`WebM`、`OGG`
- 单个视频最大 `80MB`

## 状态与错误处理

新增一个页面内本地上传状态，例如：

- `uploadingLessonVideo: boolean`

约束如下：

- 上传中禁止再次触发上传
- 上传中禁止提交课节表单
- 上传失败时清空 `<input type="file">` 的值，允许重新选择同一文件
- 上传成功后同样清空文件选择控件，避免后续选择相同文件时不触发变更事件

错误处理规则：

- 文件选择为空：不报错，直接忽略
- 接口失败：显示上传失败消息，保留原有 `lessonForm.videoUrl`
- 课节切换到 `ARTICLE` 时：沿用当前逻辑清空 `videoUrl`

## 测试策略

本次以最小可验证改动为目标，至少完成：

- 对 `admin-web` 做 TypeScript 构建或现有可用校验
- 手动验证课程后台课节页：
  - 新建视频课节时可上传并自动回填
  - 编辑已有视频课节时可看到当前视频并重新上传替换
  - 上传失败时页面能显示错误
  - 上传中保存按钮不可点击

## 风险与约束

- 本期仍依赖现有通用上传接口，因此上传能力上限由后端接口决定
- 纯上传方案会移除手工地址录入能力，若后续仍有外链视频需求，需要单独开新需求恢复双通道模式
- 当前页没有进度条，大文件上传时用户只能看到“上传中...”状态，这是本期接受的代偿约束
